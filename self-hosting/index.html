Self-hosting questions

What does self-hosting involve?

The site is a static build: HTML, CSS, JavaScript, the app modules, fonts and images. Serve those files from any static web server (nginx, Apache, Caddy, S3/CloudFront, GitHub Pages, Netlify, IIS, an internal file server). Nothing needs to run server-side, and there is no database to set up.

Do I need a commercial license to run Clausery internally for my own team?

No. The AGPL permits internal use within an organisation without source redistribution. You only need a commercial license if you want to (a) remove the visible branding and ship a rebranded version to clients, (b) integrate the editor into a closed-source product, or (c) modify the code and run the modified version as a service for third parties without releasing the modifications.

Can Clausery run completely offline / air-gapped?

Yes. Once built and served, the app makes no document-processing requests; the only requests are for its own files. If you disable the optional analytics and online-key checks, there are zero third-party requests. Offline license keys are verified with a cryptographic signature on-device.

How is data stored when self-hosted?

Exactly the same as on the public site: in the user's own browser (IndexedDB). The self-hosted server never receives document contents and has no document database. You can change the CSP and CORS to further restrict what browsers may load.

Is there a free trial for self-hosted?

You do not need one to evaluate — clone the public repository and run it locally. Pro features require a license, but you can start the 14-day no-card trial in any running copy, including a local one.

What does Enterprise / commercial licensing cost?

Enterprise pricing is by quote because deployments range from a single intranet instance to firm-wide rollouts with custom branding and template authoring. Email with your use case, number of users and whether you need branding removed.
