Client intake forms

Clients answer the questionnaire on their own computer, offline, and send you a small answers file. No portal, no accounts, and their answers never touch a server.

How it works

  1. Open any draft of the template and, on the review step, choose Create client intake form (Pro). Add a short message. Download the form: one .html file containing the questionnaire and nothing else (no document, no answers).
  2. Send the file to the client by whatever channel you already trust (email, secure file transfer). They double-click it. It opens in their browser from their disk; it needs no connection.
  3. They answer the questions, can save progress to continue later, and finally Save answers, which downloads <template>-answers.json. They send that file back.
  4. In the draft, choose Import answers and select the file. The answers are filled in; review and generate as usual.

What the client sees

A clean form with your firm name, your message, the sections and questions exactly as in the app, the same validation, and two buttons: save progress and save answers. It works in any current browser on Windows, macOS, Linux, iOS and Android (on phones the file is opened from the downloads folder).

Security notes

  • The form contains the questionnaire structure (labels, help text, options), not the Word template and not previous answers.
  • The answers file is plain JSON. Treat it like any client document: if you would encrypt an email attachment, encrypt this one too.
  • The form's Content Security Policy blocks all network access, even if it were opened from a web server.

Worked example: collect a new client's engagement details

Start a fresh draft of the engagement letter template, check its labels and help text, and export an intake form with a fictional client. The form contains the questionnaire, including any descriptions, defaults and options you configured; inspect those before sharing it. It does not contain the Word document or the current draft's answers.

  1. Tell the recipient which file to open, what information to supply and how to return the completed answers securely.
  2. Open the HTML file in a full browser rather than an email preview. Enter test details and choose Save progress.
  3. Close the form, reopen the original HTML file and choose Load saved answers to select the in-progress JSON file. Progress is restored from that file, not from a server account.
  4. Complete the required questions, choose Save answers and return the downloaded JSON, not a screenshot or the blank HTML form.
  5. In the fresh draft, choose Import answers (.json), inspect the imported values and generate a test Word document.

Review the handoff, not just the import

Importing updates matching answers in the draft; it does not automatically clear every existing value. Use a new draft for a new client and inspect fields not supplied in the file. A different-template warning needs investigation, not automatic acceptance. Questions and field names must match the template you intend to use.

The answers JSON and any saved-progress JSON are unencrypted. A passphrase on your own workspace does not protect a downloaded file in the client's Downloads folder. Agree the transfer channel, access and retention policy before asking for sensitive information. See the security model and the export and backup guidance.

Hosting the form on your site

Because the form is a single static file, you can also put it on your website or client extranet. Clients still answer locally and send back the file; nothing is posted to the server hosting the page.
